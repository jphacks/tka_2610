# 開発ガイド（おもいでミュージアム）

リポジトリ直下の [README.md](../README.md) は JPHACKS の提出用です。アプリの仕組み・起動方法・API はこのファイルにまとめています。

子どもの絵や工作を写真に撮って登録すると、3D のおうちに飾れるアプリです。
Web で写真を登録すると Rust のサーバーが 3D モデル（GLB）を作り、「おうちに飾る」を押すと、Web の 3D のおうち（three.js）の棚や机の上に並びます。作品は、作ったときの子どもの年齢（設定のお誕生日と作品の作成日から計算）ごとの「おへや」に飾ります。おへやは中央のリビング（10 × 10 m）1 部屋の家で、1 つの年齢におへやをいくつでも足せます（階として積み上がる）。アプリのホームでは年齢を選ぶと、その年齢のおへやを積み上げた建物が 3D で出て、階を押すとそのおへやに入れます。おへやの中は画面いっぱいの 3D で、ドラッグで見回せて、放っておくとゆっくり回り、作品をタップすると詳細が開きます。PC とスマホのブラウザで、家の中を一人称で歩いて見て回れます（鑑賞モード）。
作品には「おもいで」として、作っているところの動画や別の角度の写真、子どもの声を、いくつでも付けられます（作品の詳細で足す。声はアプリで録音もできる）。おへやの 3D では記録のある作品の上に印が出て、鑑賞モードでは声のある作品の前に立つと声が流れます。
家具と作品の置き場所は、配置 JSON としてデータベースに保存しています。模様替えの画面で、家具や作品を動かす・回す・消す・足す、壁紙と床材（テーマ）を選ぶ、ができます。初回の起動で、サンプルの作品 33 点（アトリエ）が登録され、作った年齢のおへや（3さい 5 点・4さい 19 点・5さい 9 点）に飾られます。4さいは 1 つのおへやに入りきらないので、2 階ができます。
3D の表示は Web（three.js）だけで完結しています。

### 作品を登録して飾るまで

```mermaid
sequenceDiagram
  actor User as 保護者
  participant Web as Web アプリ
  participant Rust as Rust API
  participant DB as PostgreSQL

  User->>Web: 写真を撮る・選んで登録
  Web->>Rust: POST /api/artworks（写真と作品情報）
  Rust->>Rust: 回転補正・縮小・サムネイル・GLB 生成（仮）・GLB の実寸を測る
  Rust->>DB: 作品を保存（実寸も）
  Rust-->>Web: 作品情報（画像 URL・日付ラベルなど）
  Web->>User: 3D プレビューを表示

  User->>Web: 「おうちに飾る」
  Web->>Rust: POST /api/artworks/:id/display
  Rust->>DB: 配置 JSON をロックして読む
  Rust->>Rust: 空いている棚や机の天板を探す（作品の実寸で。部屋の指定があればその部屋だけ）
  Rust->>DB: 配置 JSON と作品の slot_id を保存
  Rust-->>Web: 作品情報（飾った部屋の名前。例「中央のリビング」）。空きが無ければ 409

  loop 3秒ごと（鑑賞モードを開いているとき）
    Web->>Rust: GET /api/museum
    Rust-->>Web: 配置 JSON・家具の一覧・作品の置き場所
  end
  Web->>Rust: 家具と作品の GLB を取得
  Web->>Web: 家具を置き、作品を天板や棚に載せる（three.js）
```

登録のとき、Rust は飾るモデル（写真から作ったものも、渡した GLB も）の実寸（幅・高さ・奥行き）を測って、作品と一緒に保存します。おうちに置くときの大きさは、この実寸で決まります（下の「作品の大きさ」）。測れなかったときは寸法を空のままにして、登録は続けます。

置き場所は、中央のリビングの中で、作品を置ける家具を次の順に探して決めます（部屋が 2 つ以上あるときは `ROOM_DEFS` の順に部屋を探します）：飾り棚 → サイドボード → 工作机 → ローテーブル → 低い台 → 白い台座 → 細い台座 → 本棚 → ベンチ → スツール。本棚は中段 → 上段 → 下段 → 天板の順です。
`POST /api/artworks/:id/display` の本文で部屋（`room_id`）を指定したときは、その部屋の家具だけを探します（模様替えの「追加」→「作品」は、選んでいる部屋を送ります。今は `hub` だけです）。
作品を置ける面（家具の上の平らな所。本棚は各段も。`catalog.json` の `surfaces`）を作品 1 つ分の枠（幅・奥行きとも最大 0.56 m）で縦横に区切り、手前（家具の正面側）の並びから、端から順に空いているところに置きます。幅・奥行きは、枠を 0.5 m 以上に保てる数で等分します。今の家具で 2 並びになるのは低い台（枠の奥行き 0.545 m）だけで、ほかは横 1 列です。空いているかどうかは、置く作品と、すでに載っている作品の置いた後の大きさで調べます（寸法の分からない作品は枠そのものの大きさ）。
全部埋まっているときは、409 で「飾る場所がいっぱいです。模様替えで棚や机を足してください」が返ります。部屋を指定したときは、その部屋が埋まっていれば 409 で「中央のリビング に飾る場所がいっぱいです。模様替えで棚や机を足してください」のように返り、ほかの部屋には置きません。下の「模様替え」で作品を置ける家具（棚・机・台など）を足すか、飾っている作品を外すと、また飾れます。

### 模様替え（家具と作品を動かす）

おへや（`/rooms/:id`）の右下の「模様替え」（ソファの丸いボタン）か、「おうちの中」の「⋯」→「模様替え」から開きます（URL は `/home/edit?room=<おへやの id>`。模様替えするのはそのおへや）。手前の壁の上の部分をカットした家（リビング）を斜め上から見下ろして、家具と作品を動かせます。

| 操作 | やり方 |
|---|---|
| 部屋を選ぶ | 今はリビングだけなので、部屋の切り替えは出ない。「追加」と「テーマ」はリビングに入る（部屋が 2 つ以上あるときは、画面の下で部屋を切り替えると、カメラがその部屋へ寄り、「追加」と「テーマ」はその部屋に入る。シートの題も「追加（〇〇）」になる） |
| 選ぶ | 家具や作品をタップ（クリック）する。何もない床をタップするか Esc で、選ぶのをやめる |
| 動かす | 選んだ物をドラッグする。物は自分の部屋（リビング）の中でだけ動く。家具は床の上で動き、家具を動かすと上の作品も一緒に動く。作品は、指した家具（同じ部屋の家具）の天板や本棚の段（指した高さの段）に載せ換えられ、家具の無い所を指したとき（作品を置けないソファ・ラグなどを指したときも）は床に置かれる。家具も作品も、置ける範囲の縁（家具と床の作品は壁から 12 cm、家具の上の作品は面の平らな所の縁）で止まり、縁に沿って滑る。ほかの物と重なる場所では足もとの板が赤くなり、そこで離すと元の位置に戻る（出入口のある部屋では、出入口の前も赤くなる。今の家には出入口が無い） |
| 回す | 「回す」か R キーで 90° ずつ回す。回して面や部屋からはみ出す分は、内側へ寄せる。奥行きの浅い面（サイドボード・飾り棚・ベンチ・本棚など）では、回すと作品が小さくなることがある（下の「作品の大きさ」）。ほかの物と重なるときは回さない |
| 消す | 「消す」か Delete（Backspace）キー。家具を消すと、上の作品も一緒に外れる（作品は「飾っていない」に戻るだけで、作品そのものは消えない） |
| 元に戻す | 「元に戻す」で 30 回まで戻せる |
| 上げ下げ | 壁の家具を選ぶと「回す」の代わりに「上へ」「下へ」が出て、10 cm ずつ上げ下げできる（掛けられる高さの範囲の中で。下の家具や、上に飾る作品の場所と重なる高さには下げられない） |
| 足す | 「追加」→「家具」で 17 種類の家具から選ぶ（部屋の中央に近い空いている所に置かれる。「壁に掛ける」の付いた家具は、北・西・東・南の壁の順に、壁の中央に近い空いている所に、家具ごとの高さで掛かる）。「追加」→「作品」で、そのおへやの年齢の飾っていない作品を選ぶと、空いている天板に飾る（置き場所はサーバーが選ぶ。空きが無ければ「〇〇 に飾る場所がいっぱいです」と出る） |
| テーマ | 「テーマ」で、壁紙と床材の組み合わせを 9 種類から選ぶ（テーマは部屋ごとに持つ。下の「おうち（リビング）」） |

変えた配置は、最後の操作から 0.6 秒後に自動で保存されます（`PUT /api/home/layout`）。保存のボタンはありません。画面を離れるとき、タブを閉じる・再読み込みするときも、保存していない変更を送ります。
置けるかどうかは、画面でも、保存のときのサーバー（Rust）でも、同じ決まりで調べます。サーバーが受け付けなかったときは、その理由がお知らせに出て、配置はサーバーに保存されているものに戻ります。
ドラッグ中は縁で止まるので、板が赤くなるのは、ほとんどがほかの物と重なるときです（寸法の分からない作品を奥行きの浅い面で 90° 回すと、はみ出しで赤くなることがあります）。
部屋の大きさを変えることと、物を別のおへやへ移すことは、まだできません（おへやを増やすのはホームの「おへやを足す」）。
PC の広い画面では、スマホの枠をやめてウィンドウいっぱいに広がります。右上の「鑑賞モードへ」で、そのまま家の中を歩けます（スマホでも出ます。スマホではタッチで歩きます）。

### おうち（リビング）

家は中央のリビング（10 × 10 m）の 1 部屋だけです。壁の高さは 3.2 m で、4 面の壁はすべてふさがっていて、出入口はありません。
部屋の形（位置・大きさ・出入口）は `backend/src/home.rs` の `ROOM_DEFS` にだけ書いてあり、`/api/museum` の `house` で Web に渡します。Web には部屋の数値を書いていません。

```
              N (-Z)
     +-------------------+
     |                   |
     |                   |
     |       hub         |
     |      (0, 0)       |
     |    10 x 10 m      |
     |                   |
     |                   |
     +-------------------+
              S (+Z)
```

上が北（−Z）、下が南（+Z・入口側）です。かっこの中は部屋の中心の世界座標 (x, z) です。線は壁の外の面で、家全体は x −5.24〜5.24、z −5.24〜5.24 に収まります。

| 部屋 id | 名前（画面・エラーの文言） | 中心 (x, z) | 内寸 | 出入口 | 初期配置のテーマ |
|---|---|---|---|---|---|
| `hub` | 中央のリビング | (0, 0) | 10 × 10 m | なし（4 面とも壁） | ナチュラル |

- 座標はメートルです。リビングの中心が世界の原点で、床が y = 0、+X が東（右）、+Z が南（手前・入口側）です。
- 家具と床の作品の位置は、所属する部屋（今はいつも `hub`）の中心から見た位置です（世界座標 = 部屋の中心 + 位置）。部屋は平行移動だけで、回しません。
- 壁の厚さは 0.24 m です（内の面 ±5.0、外の面 ±5.24）。
- 以前は、リビングの西・東・北に 8 × 8 m の左・右・前の部屋（`left`・`right`・`front`）があり、リビングの壁の中央の出入口（通れる幅 2.10 m・高さ 2.60 m のアーチ）でつながっていました。今は消しています（以前の値は git の履歴にあります。戻し方は [AGENTS.md](../AGENTS.md) の「構成」）。
- 出入口の前には物を新しく置いたり動かしたりできない、という決まり（壁に沿って出入口の中心から ±1.27 m、壁の内側の面から部屋の中へ 1.15 m）はコードに残っています。出入口を戻したときに使われます。今は何も止まりません。
- 斜め上から見る画面（ホーム・おうちの中・マップ・模様替え）では、手前（カメラの側の 2 面）の壁の上の部分をカットして、部屋の中が見えるようにしています。カットする壁はカメラの向きに合わせて入れ替わるので、どの向きからでも家の中を見回せます。部屋が 2 つ以上あるときは、部屋どうしの間の壁（出入口のある壁）もカットします。3D プレビューは手前の壁だけ、鑑賞モードはカットしません。

建物の GLB は部屋ごとに 1 つずつで、今は `backend/static/models/rooms/hub.glb` だけです（出入口の無い 4 面の壁・床・幅木などが入っています。家具と作品は配置 JSON から置きます）。部屋の中心が原点で、Web が部屋の中心へ平行移動して置きます。サーバーは起動時に `backend/data/media/museum/room-<部屋 id>-<版>.glb` へコピーして、`house.rooms[].model_url` で配信します。

> [!IMPORTANT]
> 今入っている `hub.glb` は **開発用のシェル** です。キット v1 の部品から `tools/home-rooms/build_rooms.py` で生成したもので（作り方は [tools/home-rooms/README.md](../tools/home-rooms/README.md)）、本番の GLB は別に作ってもらって同じファイル名で置き換えます。仕様は [docs/house-assets.md](./house-assets.md) にあります。
> 置き換えるときは、`python3 tools/home-rooms/check_rooms.py <GLB のフォルダ>` で確かめてから、`backend/static/models/rooms/` の同じ名前のファイルを上書きします（別のフォルダのまま試すときは、環境変数 `HOME_ROOM_MODELS_DIR` にそのフォルダを指定します）。サーバーを起動し直すと、ファイルの大きさと更新日時から配信の URL が変わるので、ブラウザに古い GLB が残ることはありません。

- 部屋の GLB が見つからない部屋は、起動ログに `[Museum] <パス> が見つかりません (警告: この部屋の建物は表示されません (house.rooms[].model_url は null))` と出ます。サーバーは起動し、Web はその部屋の建物だけを描きません。
- 部屋ごとの GLB にする前の、リビングだけの 1 つの GLB `backend/static/models/home-empty.glb`（8 × 8 m。部屋を広げる前の大きさ）は消さずに残しています。今も `MUSEUM_MODEL_PATH` の既定値で、`/api/museum` の `model_url` として返します（前の版の Web のため）。今の Web は `house` があれば `model_url` を使いません。

作品は、作品を置ける家具（棚・机・台・本棚の段・ベンチ・スツール）の上の平らな所に飾ります。置ける範囲は家具のモデルから測った平らな面で、ローテーブルや工作机の丸い縁には置けません。初期配置の家具はすべて中央のリビングにあり、作品の置き場所が 17 あります（飾り棚 2・サイドボード 3・工作机 2・ローテーブル 2・低い台 6・白い台座 1 × 2）。初回の起動で登録されるサンプルの作品 33 点は、ここに並びます。模様替えで作品を置ける家具を足すと、置き場所が増えます。

| サイドボード | `home_console` | 3 | 1 |
| 飾り棚 | `home_display_shelf` | 2 | 1 |
| 工作机 | `home_craft_desk` | 2 | 1 |
| 本棚 | `home_bookshelf` | 5（3 つの段に 1 つずつ・天板に 2） | 0 |
| スツール | `home_stool` | 1 | 0 |
| ラグ | `home_rug` | なし（ほかの家具と重ねて置ける・上を歩ける） | 1 |
| フロアライト | `home_floor_lamp` | なし | 1 |
| 観葉植物 | `plant` | なし | 1 |

| ベンチ | `bench_oak` | 2 | 0 |

| ピクチャーレッジ | `wall_picture_ledge_french_oak` | 2（奥行き 13 cm の浅い棚。作品は小さく飾られる） | 0 |

下の 3 つは壁に掛ける家具です（`placement: "wall"`。GLB は `backend/static/home/modules/` に、テクスチャを 1024px 以下に縮めて入れた）。
- 背面を部屋の壁の内側の面に付けて掛けます（向きは壁に合わせて 90° ごと）。模様替えでは、ドラッグするといちばん近い壁に付き、壁に沿って動きます。ほかの壁へ動かすと、向きも変わります。
- 配置 JSON の `position` の y が底面の高さです（キャビネット 1.3 m・飾り棚 1.5 m・ピクチャーレッジ 1.2 m で掛かる）。0.3 m から、上に飾る作品の枠まで壁の高さ（3.2 m）に収まるところまで上げ下げできます（キャビネットは 1.88 m・飾り棚は 2.49 m・ピクチャーレッジは 2.61 m まで）。
- 下の床の家具とは、高さが重ならなければ同じ場所に置けます。床の家具は、家具の高さか、天板に飾る作品の枠の上までの場所を取ります（ソファの上なら 0.99 m より上、サイドボードの上なら 1.52 m より上）。
- 作品を自動で飾るときは、ほかの家具がいっぱいになってから使います。
- キャビネットの中の棚（扉を開けると使える面）は、扉を閉じたままにしているので使いません。

壁紙と床材は、次の 9 種類のテーマから選べます（`catalog.json` の `themes`）。選んだものは配置 JSON の `rooms.hub.wall`・`rooms.hub.floor`（部屋ごと）に入り、鑑賞モードを含むすべての 3D 画面に付きます。初期配置のテーマは上の部屋の表のとおりです。
部屋を戻して隣の部屋と壁を共有するときは、共有する壁の隣の部屋に向いた面（建物の GLB で `faceRoom` の印が付いた面）に、その部屋の壁紙が付きます。

| テーマ | 壁紙（`wall`） | 床材（`floor`） |
|---|---|---|
| ナチュラル | 白壁 `plaster` | オーク `oak` |
| 木のおうち | オーク `oak` | オーク `oak` |
| レンガ | レンガ `brick` | 石材 `limestone` |
| 北欧ホワイトオーク | 白い塗り壁 `nordic_chalk` | ホワイトオーク `white_oak` |
| セージグリーンとアッシュ | セージの塗り壁 `sage_limewash` | アッシュ `pale_ash` |
| 白大理石 | 白い塗り壁 `nordic_chalk` | 白大理石 `carrara_marble` |
| 黒大理石 | マッシュルーム色の塗り壁 `mushroom_limewash` | 黒大理石 `nero_marble` |
| レンガとオーク | 淡いレンガ `soft_brick` | ホワイトオーク `white_oak` |
| ウォールナットとクリーム | クリームの塗り壁 `warm_cream` | ウォールナット `warm_walnut` |

下の 6 種は内装セット（`backend/static/home/textures/finish-pack/`。出どころは同じフォルダの `README.md`）です。変わるのは壁と床だけで、幅木・枠・土台は GLB の木目のままです（セットの見本の GLB は、幅木・枠もテーマの色に塗っています）。
内装セットのテーマを共有のデータベースで使い始めるときは、先に全員が更新して古いサーバーを止めてください（下の「共有のデータベースを使うとき」）。

#### 作品の大きさ

作品は、登録のときに GLB から測った実寸（幅・高さ・奥行き）を、置き場所の枠に収めた大きさで置きます（`backend/src/home.rs` の `display_scale`）。

- 枠は、家具の上なら面ごとの `art_fit`、床なら幅 0.8 × 高さ 1.0 × 奥行き 0.8 m です。`art_fit` の幅・奥行きは最大 0.56 m（面を等分した 1 つ分）で、高さは 0.62 m です。本棚の段では上の棚板にぶつからない高さ（すき間 − 4 cm。0.34〜0.36 m）、スツールは 0.3 × 0.3 m です。
- 作品の向きで回したときの縦横と高さが枠に収まる、いちばん大きい倍率にします。そのため、奥行きの浅い面で 90° 回すと、奥行きに収まるまで小さくなります（帆船（幅 0.56 m・奥行き 0.34 m）をサイドボード（枠の奥行き 0.48 m）で 90° 回すと 0.86 倍）。
- 渡した GLB とサンプルの作品 33 点（`model_kind` が `custom`）は実寸のモデルなので、1 倍より大きくしません。枠に収まれば実寸のまま、収まらなければ縮めます。サンプルの 33 点は、どの面にも床にも、0° でも 90° でも置けます（本棚の段とスツールでは、どれも縮みます）。
- 写真から作った額縁・スタンド（仮の実装）は、枠いっぱいの大きさにします。生成するモデルは枠より大きいので、縮みます（800 × 600 の写真の額縁は幅 1.35 m なので、サイドボードでは約 0.41 倍）。
- 寸法が分からない作品（GLB を測れなかった作品）は、今までどおり枠そのものを作品の大きさとして判定し、表示は枠に収めます。
- 置けるかどうか（はみ出し・重なり）も、この置いた後の大きさで調べます。倍率は `/api/museum` の `slots[].scale` で返します。

家具と作品の置き場所は、おへやごとに配置 JSON としてデータベースの `house_rooms.layout` に保存しています（前の `home_layout` は、最初の起動でおへやに分けたあとは使いません）。形は次のとおりです（型と検証は `backend/src/home.rs`）。

```jsonc
{
  "schemaVersion": 5,
  "kitVersion": "1.1.0-home",
  "rooms": {
    // hub だけ（ほかの部屋があると 400）。enabled はいつも true、大きさは 10 × 10 に決まっている
    "hub": { "enabled": true, "width": 10, "depth": 10, "wall": "plaster", "floor": "oak" }
  },
  "objects": [
    { "kind": "furniture", "id": "home-005", "assetId": "home_console", "roomId": "hub",
      "position": [2.7, 0, 1.55], "rotationY": -1.5707963267948966 },
    { "kind": "artwork", "id": "art-3f9a1c2e", "artworkId": "<作品の id>", "parentId": "home-005",
      "position": [0.56, 0, 0], "rotationY": 0 },
    { "kind": "furniture", "id": "home-012", "assetId": "home_bookshelf", "roomId": "hub",
      "position": [-3.5, 0, -4.5], "rotationY": 0 },
    { "kind": "artwork", "id": "art-7b21d0aa", "artworkId": "<作品の id>", "parentId": "home-012",
      "surface": "shelf2", "position": [0, 0, 0], "rotationY": 0 },
    { "kind": "artwork", "id": "art-0c4d9e11", "artworkId": "<作品の id>", "roomId": "hub",
      "position": [1.5, 0, 3.5], "rotationY": 0 }
  ]
}
```

- 座標はメートルです。床が y = 0、家具の正面は +Z、`rotationY` はラジアンです。`position` の y は、壁の家具の底面の高さだけに使います（床の家具と作品はいつも 0。0 以外を送っても 0 にする）。
- 家具と、床に置く作品の `position` は、`roomId` の部屋の中心から見た位置です（今の部屋は hub だけで中心が原点なので、世界座標と同じです）。`roomId` は `hub` だけで（ほかは 400）、家具には必須、床の作品は省くと `hub` です。
- `parentId` のある作品は、親の家具の面（`surface`）に載り、部屋は親の家具の部屋です（`roomId` を書いても使いません）。`surface` を省くと天板（`"top"`）で、本棚の段は `"shelf1"`（下段）・`"shelf2"`（中段）・`"shelf3"`（上段）です。`position` は、親の家具を回す前の向きで、その面の中心からの位置です。
- この配置 JSON だけは camelCase です（家のキットの JSON と同じ形）。ほかの API の項目は snake_case です。
- 保存するときに Rust が検証します（`home.rs` の `check_placement`）。家具と床の作品は自分の部屋の壁から 12 cm 空ける（部屋ごとの範囲。リビングは ±4.88）、壁の家具は背面を壁に付けて決まった高さの範囲に掛ける、物どうしは足元と高さの範囲の両方で重ならない（ラグは除く。部屋が 2 つ以上あるときも、比べるのは同じ部屋の中だけ）、作品は面の平らな所からはみ出さない・同じ面の作品と重ならない、などです（作品の大きさは上の「作品の大きさ」）。置けない配置は 400 になります。模様替えの画面は、同じ決まりを `web/src/three/scenes/home/placement.ts` で先に調べます。
- 出入口の前は、出入口のある部屋でだけ調べます（今の家には出入口が無いので、何も止まりません）。出入口を戻したときは、保存のときに **新しく置いた物と、動かした・回した・別の部屋へ移した物だけ** を調べます（`home.rs` の `DoorPolicy::OnlyMoved`。保存されている配置と比べて決める）。前から出入口の前にある物は、動かさなければそのまま読めて、保存もできます。起動時の整理・作品を外す・作品を消すときは調べません。作品を飾るときは、置いた作品だけを調べます。
- 保存されている配置が検証に通らないとき（別の版のサーバーが、この版の知らない面に作品を置いて保存したときなど）は、置けない作品だけを外して読みます。起動時にはその配置を保存し直し、外した作品を空いている場所に置き直します。家具や部屋がおかしいときだけ、初期配置に戻します。
- `schemaVersion` 1（家のキットの JSON）・2（リビングだけの家）・3（部屋を広げる前の 8 × 8 と 6 × 6 の 4 部屋）・4（10 × 10 と 8 × 8 の 4 部屋）の配置は、読むときに自動で 5 に上げます。リビングは今の大きさにし、リビングの壁紙・床材はそのままです。左・右・前の部屋にあった家具・床の作品と、その家具の上の作品は配置から外します（`home.rs` の `drop_legacy_rooms`）。外した作品は、起動時の整理（`reconcile`）がリビングの空いている所へ置き直し、空きが無ければ「飾っていない」に戻します。v3 までの配置は、リビングが広がった分（1 m）、壁から 0.6 m 以内にあった家具と床の作品を、その壁の方へ動かします（壁に付けて置いた棚などが、広がった部屋の中で浮かないように。ほかの物は動かさないので、物どうしが新しく重なることはありません）。起動時に上げたときは、5 にした配置をおへやごとに保存し直します（ログは `[Home] rooms loaded (〇 rooms, 〇 saved again)`）。データベースの `house_rooms.schema_version` 列にも、保存した配置の版（5）が入ります。
- `wall` は `plaster`・`oak`・`brick`・`limestone`・`nordic_chalk`・`sage_limewash`・`mushroom_limewash`・`warm_cream`・`soft_brick`、`floor` は `oak`・`limestone`・`white_oak`・`pale_ash`・`warm_walnut`・`carrara_marble`・`nero_marble` のどれかです（`home.rs` の `WALLS`・`FLOORS`）。部屋の大きさは変えられません（違う大きさは 400）。

### 3D モデルの生成について（仮）

> [!IMPORTANT]
> 現在の GLB 生成は、動作を確認するための仮の実装です。

今は写真そのものを板に貼り、次の 2 種類の形にしているだけです。作品の形を立体として復元するものではありません。

| 作品の種類 | 今の 3D モデル |
|---|---|
| 絵画・写真・その他 | 額縁に入れた絵 |
| 工作 | アクリルスタンド風の板 |

生成処理は `backend/src/glb.rs` にまとまっています。
登録時に `.glb` ファイルを渡すと、生成したモデルの代わりにそのファイルを飾ります（Web の登録画面の「3Dモデル(.glb)を持っている場合」）。
生成したモデルも渡した GLB も、登録のときに大きさを測り、その実寸をもとに置きます（上の「作品の大きさ」）。渡した GLB とサンプルの作品 33 点は実寸のモデルとして扱い、置き場所より小さくても拡大しません。

## 起動方法

### 必要なもの

| ツール | バージョン |
|---|---|
| PostgreSQL 16 | Docker Desktop（`docker compose`）か、Homebrew の `postgresql@16` |
| Rust | 1.88 以上（edition 2024） |
| Node.js | 20.19 以上（Vite 8） |

### 1. 環境変数ファイルを作る

リポジトリ直下の `.env.example` をコピーして `.env` を作ります（`.env` は git に含めていません）。

```sh
cp .env.example .env          # macOS / Linux
# Copy-Item .env.example .env # Windows（PowerShell）
```

`DATABASE_URL` は必須で、ないとサーバーが起動しません。データベースは次のどちらかを使います。

- **Supabase（共有のデータベース）**: `.env.example` のコメントにある形で `DATABASE_URL` を書き換えます。パスワードは管理している人から受け取ってください。Supabase のダッシュボードの「Connect」→「Session pooler」でも確認できます。
- **ローカルの PostgreSQL**: `.env.example` の値のままで、`docker-compose.yml` のデータベース（または同じユーザー名・DB 名で作った Homebrew の PostgreSQL）につながります。

### 2. データベースを起動する（ローカルの PostgreSQL のときだけ）

Supabase を使うときは、この手順は不要です。

先に Docker Desktop を起動し、画面左下が「Engine running」になるまで待ちます。
Docker Desktop は WSL 2 の上で動きます。WSL を自分で起動する必要はありません。

```powershell
docker compose up -d db
```

Docker を使わない macOS では、Homebrew の PostgreSQL 16 で同じユーザー名・DB 名を作ります（初回だけ）。

```sh
brew install postgresql@16
PG=/opt/homebrew/opt/postgresql@16/bin
$PG/initdb -D /opt/homebrew/var/postgresql@16 --locale=C -E UTF8
$PG/pg_ctl -D /opt/homebrew/var/postgresql@16 -l /opt/homebrew/var/postgresql@16/server.log start
$PG/psql -h 127.0.0.1 -d postgres -c "CREATE ROLE museum LOGIN PASSWORD 'museum';" -c "CREATE DATABASE museum OWNER museum;"
```

### 3. Web アプリをビルドする

```powershell
cd web
npm install
npm run build
```

### 4. サーバーを起動する

```powershell
cd backend
cargo run
```

http://localhost:8080 を開くと Web アプリが表示されます。
初回の起動では、次のことが自動で行われます。ログは、空のデータベースで起動したときのものです。

- マイグレーション（作品の実寸の列 `model_width`・`model_height`・`model_depth`、子どものお誕生日 `museum_settings.child_birthday`（`010_child_birthday.sql`。デモの値 2021-06-01 が入る）、おへやの表 `house_rooms` と作品の列 `artworks.house_room_id`（`011_house_rooms.sql`）もここで作られます。作品のおもいでの表 `artwork_memories`（`012_artwork_memories.sql`）もここで作られます。`008_wider_rooms.sql`・`009_single_room.sql`・`011_house_rooms.sql` は古いサーバーを止める番兵も兼ねます。012 は番兵ではありません）
- 家の GLB の圧縮。家の建物（`backend/static/models/rooms/hub.glb`）と、前の版の Web 用の `home-empty.glb` を `backend/data/media/museum/` にコピーして gzip 版を作ります（初めてのときだけ `[Museum] Prepared room-hub model: … KB -> … KB (gzip)` のように出ます）
- 寸法の無い作品の GLB を測って、実寸を入れる（`[Artwork] model sizes: measured 0, skipped 0 (missing file), failed 0` と出ます）
- 今の年齢（5さい）のおへやを、初期配置（`backend/static/home/default-layout.json`。家具 11 個）で作る（`[Home] 今までの配置をおへやに分けました (5 さい。…)`・`[Home] rooms loaded (1 rooms)` と出ます）
- サンプルの作品 33 点の登録と飾りつけ（`[Seed] atelier: inserted 33, repaired 0 files, redated 0, placed 33` と出ます。作った年齢のおへやの棚や机に並び、3さい・4さいのおへやは飾るときに作られます。4さいのおへやがいっぱいになると `[Home] 4さいのおへや 2 を足しました (サンプルの作品を飾るため)` と出て 2 階ができます）

おへやとサンプルの作品は、データベースにまだ無いときだけ作ります。2 回目からは `inserted 0` になります。
前の版（おへやの無い、`home_layout` 1 つの家）のデータベースで起動すると、はじめに 1 回だけ、その配置を年齢ごとのおへやに分けます（飾っている作品のある年齢と今の年齢の 1 階。どのおへやも同じ家具とテーマで、作品はその年齢の物だけを同じ位置のまま入れる）。そのあと `[Home] reconcile: relocated 〇, unplaced 〇, removed 〇` で、年齢の合わない所にある作品を正しいおへやへ置き直します。設定でお誕生日を変えたときも、同じように作品が年齢のおへやへ移ります（空きが無ければ「飾っていない」に戻ります）。
`schemaVersion` 2〜4 の配置は、読むときに v5 に上げて保存し直します（`[Home] rooms loaded (〇 rooms, 〇 saved again)`）。左・右・前の部屋にあった物は外れ、そこにあった作品はリビングに空きがあれば置き直されます（無ければ「飾っていない」に戻ります）。v3 までの配置では、壁ぎわの物が広がった壁の方へ動きます。ほかの物はそのままです。共有のデータベースで初めて行うときは、先に全員が更新して古いサーバーを止めてください（下の「共有のデータベースを使うとき」）。
作品の実寸は、登録のときに測ります。実寸の列を足す前に登録した作品は、起動のときに GLB を測って入れます（`measured` がその数）。この PC に GLB が無い作品は飛ばします（`skipped`。サンプルの 33 点は、seed が GLB を作り直したときに測ります）。
博物館のころに展示していた作品は、起動時に空いている棚や机へ置き直します。空きが無ければ未展示に戻します。
サンプルの作品のモデルを入れ直すときの縮め方は [backend/static/atelier/README.md](../backend/static/atelier/README.md) にあります（npm で証明書のエラーが出るときは `NODE_EXTRA_CA_CERTS=/etc/ssl/cert.pem` を付けます。macOS）。

### 5. 鑑賞モード（家の中を歩く）

ホームの右下の「歩く」（人の丸いボタン）を押すか、「おうちの中」を開き、右上の「⋯」→「鑑賞モード」を選びます（URL は `/museum/walk`）。「おうちのマップ」の「⋯」と、模様替えの画面の右上の「鑑賞モードへ」からも開けます。PC でもスマホでも使えます。
PC は、クリックで歩き始め、W A S D で歩く、マウスで見回す、Shift で速く歩く、Esc で操作をやめる、です。照準を作品に合わせて E かクリックで、作品の情報を出せます。
スマホは、「歩き始める」を押し、画面の左側に置いた親指（仮想スティック）で歩き、右側を指でなぞって見回します。照準を作品に合わせて「見る」で、作品の情報を出せます。右上の「やめる」で操作をやめます。スマホでは、画面の仕上げ（隅の陰・光のにじみ）を省いた軽い表示になります。
PC でスマホの操作を試すときは、URL に `?input=touch` を付けて開きます（[docs/walk.md](./walk.md) の「操作の種類の決め方」）。
はじめはリビングの南側に立っています。歩けるのはリビングの中だけです（出入口はありません）。家具や壁には当たって止まります。ラグの上は歩けます。
ほかの端末で飾る・外す・模様替えをすると、3 秒ほどで反映されます。詳しくは [docs/walk.md](./walk.md) を見てください。

### 毎回の起動（2 回目から）

1. データベースを起動します。
   - Docker を使うとき：Docker Desktop を起動してから、リポジトリ直下で `docker compose up -d db`
   - Homebrew の PostgreSQL を使うとき：`/opt/homebrew/opt/postgresql@16/bin/pg_ctl -D /opt/homebrew/var/postgresql@16 -l /opt/homebrew/var/postgresql@16/server.log start`
2. サーバーを起動します。`[DB] PostgreSQL connected` と `[DB] Migration completed` が出ればつながっています。

   ```sh
   cd backend
   cargo run
   ```

3. http://localhost:8080 を開きます。Web アプリのコードを変えたときだけ、`web` で `npm run build` をやり直します（画面を直しながら試すときは、下の「開発するとき」）。

### 共有のデータベースを使うとき

チームで 1 つのデータベース（Supabase など）を使うときは、`.env` の `DATABASE_URL` をその接続文字列にします（パスワードは各自の `.env` にだけ書きます）。Supabase は Session pooler（ポート 5432）の接続文字列を使います。作業の記録は [supabase.md](./supabase.md) にあります。

- 新しいマイグレーションや、壁紙と床材の新しい名前を共有のデータベースで使うときは、先に全員が最新を pull してビルドし直し、古いサーバーを止めます。古いサーバーは新しい配置を読めないと、初期配置に戻して保存してしまうためです（[AGENTS.md](../AGENTS.md) の「守ること」）。
- Supabase の無料プランは、しばらく使わないとプロジェクトが一時停止（Paused）します。つながらないときは、ダッシュボードで「Restore」してから起動し直します。

### 開発するとき

サーバーを起動したまま、別のターミナルで Vite の開発サーバーを使います。
`/api`・`/media`・`/home-assets` へのリクエストは 8080 番に中継されます。

```powershell
cd web
npm run dev
```

http://localhost:5173 を開きます。

テストと確認は次のとおりです。

```powershell
cd backend
cargo test
```

```powershell
cd web
npm run build
npm run check:placement
npm run check:theme
```

`npm run check:theme` は、壁紙と床材（`theme.ts`）を本物の建物の GLB と `catalog.json` で当ててみて、材質の作り・上下の壁の継ぎ目・連続して切り替えたときの競合を確かめます（ブラウザと GPU は使いません。画像も読みません）。GLB のある部屋だけを調べるので、今は `× 1 部屋（hub）` と出ます。隣の部屋の GLB があるときは、共有する壁の表と裏も確かめます。

`cargo test` では、総当たり表を作り直すテスト 1 件だけを、ふだんは飛ばします（86 件が通り、1 件が ignored）。
`npm run check:placement` は、Rust のテストと同じ総当たり表（`backend/src/testdata/placement-cases.json`。リビングだけの家の表で、4,900 件と、重なり・壁・床の台座・壁の家具などの 21 件）を Web の `placement.ts` で計算し直し、置けるかどうか・縁に寄せた位置・作品の倍率が Rust と同じかを確かめます。置き方の決まりを変えたときは、`cargo test` と両方を通してください（表の作り直し方は [AGENTS.md](../AGENTS.md) の「守ること」）。
開発用の建物 GLB を作り直したとき・本番の GLB に置き換えるときは、`python3 tools/home-rooms/check_rooms.py` でも確かめます（[tools/home-rooms/README.md](../tools/home-rooms/README.md)）。

### スマホで見るとき

PC と同じ Wi-Fi につないで `http://<PC の IP アドレス>:8080` を開きます。
つながらないときは、Windows のファイアウォールで 8080 番を許可してください。
スマホなど指で操作する端末では、作品の GLB が重いので、カメラに近い作品 6 つだけを表示します（模様替えの画面では、どの作品も選べるように全部表示します）。
鑑賞モードは、スマホではタッチで歩きます（左の親指の仮想スティックで歩き、右の指でなぞって見回す）。開発サーバー（`npm run dev`）を使うときは `http://<PC の IP アドレス>:5173` を開きます。
ブラウザは https か localhost で開いたときだけマイクを使わせるので、`http://<PC の IP アドレス>` で開いたスマホでは、おもいでの「声を録音する」が使えません（理由を出して、録音したファイルを選ぶ方へ案内します）。写真・動画・音声ファイルを選んで足すのは使えます。

### 別の PC のサーバーにつなぐとき

作品の画像と GLB は、サーバーを動かしている PC の中にだけ保存されます（データベースを Supabase にしても同じです）。
各自の PC でサーバーを動かすと、ほかの人が登録した作品の画像と 3D は表示されません。
ただし、サンプルの作品 33 点だけは、どの PC のサーバーも起動のたびに `backend/static/atelier/` から足りない画像と GLB を作り直すので、表示されます。
同じ作品をみんなで見るときは、1 台でサーバーを動かして、ほかの PC からそこにつなぎます。

1. サーバー PC のファイアウォールで 8080 番を許可します。
2. ほかの PC のブラウザでは `http://<サーバー PC の IP アドレス>:8080` を開きます。

## 困ったとき

| 症状 | 対処 |
|---|---|
| `cargo` が見つからない | Rust をインストールしたあと、ターミナルや VS Code を開き直す |
| Windows の `cargo run` で `linker link.exe not found` と出る | C++ のリンカが入っていない。Build Tools for Visual Studio をインストールし、「C++ によるデスクトップ開発」のワークロードを入れてから、ターミナルを開き直す |
| `DATABASE_URL is not set` と出る | `.env` がない。リポジトリ直下で `cp .env.example .env`（Windows は `Copy-Item .env.example .env`）を実行する |
| `500 pool timed out` と出る | データベースが止まっている。ローカルなら `docker compose up -d db`（Homebrew なら `pg_ctl … start`）で起動する。Supabase なら、ダッシュボードでプロジェクトが一時停止（Paused）していないか確認する |
| `migration failed: VersionMismatch` と出る | 適用済みのマイグレーションファイルが書き換えられている。改行コードだけの違いは起動時に自動で直るので、それ以外の変更を元に戻す |
| `migration failed: VersionMissing(6)` と出る | 共有のデータベースに、手元のコードにまだ無いマイグレーション（`006_artwork_model_size.sql`。作品の実寸の列）が適用されている。最新を pull してから `cargo run` でビルドし直す。006 より前から起動したままのサーバーがあれば止める（古いサーバーは、実寸でしか置けない作品を外してしまう） |
| `migration failed: VersionMissing(7)`・`VersionMissing(8)`・`VersionMissing(9)` と出る | データベースに、手元のコードにまだ無いマイグレーション（7 は `007_home_rooms.sql`（4 部屋の家）、8 は `008_wider_rooms.sql`（部屋を広げた家）、9 は `009_single_room.sql`（リビングだけの家））が適用されている。わざと起動できないようにしている（古いサーバーは新しい版の配置を読めず、初期配置に戻して保存してしまうため）。最新を pull し、`cargo run` でビルドし直す。共有のデータベースなら、上の「共有のデータベースを使うとき」 |
| 「飾る場所がいっぱいです」と出る | 棚や机の置き場所（初期配置では 17。すべて中央のリビング）が全部埋まっている。サンプルの 33 点で初めから 13 か所が埋まっている。模様替え（ホームの「模様替え」）で「追加」→「家具」から作品を置ける家具（棚・机・台・本棚・ベンチ・スツール）を足すか、飾っている作品を選んで「消す」で外す。作品の詳細画面の「⋯」→「飾るのをやめる」でも外せる |
| 模様替えで「〇〇 と 〇〇 が重なっています」などと出て、物が元の位置に戻る | そこには置けない。家具はほかの家具（ラグは除く）や床の作品と、作品は同じ面の作品（床なら家具やほかの床の作品）と重ならない所に置く。ドラッグ中は、家具と床の作品は自分の部屋の壁から 12 cm、家具の上の作品は面の平らな所の縁で止まるので、「壁に近すぎます」「はみ出しています」はほとんど出ない（寸法の分からない作品を奥行きの浅い面で 90° 回したときは、はみ出しになることがある） |
| 左・右・前の部屋にあった家具や作品が無くなった | 今の家はリビングだけなので、v4 までの配置を v5 に上げるときに、左・右・前の部屋の物を外している。外れた作品はリビングに空きがあれば置き直され、無ければ「飾っていない」に戻る。模様替えで作品を置ける家具を足してから、「追加」→「作品」で飾り直す |
| `localhost:5173` で別のアプリが開く | ほかのプロジェクトの Vite が 5173 番を使っている。そちらを止めるか、http://127.0.0.1:5173 を開く |
| `failed to bind port 8080` と出る | 別のサーバーが動いている。止めるか、`$env:PORT="8081"` を設定してから起動する |
| 「Web 画面が未ビルドです」と表示される | `web` で `npm run build` を実行する |
| 鑑賞モードが「おうちを表示できませんでした」になる | 画面に出る理由を見る。WebGL が使えないブラウザか、家の GLB を読み込めていない（サーバーが動いているか、`HOME_ROOM_MODELS_DIR`（既定は `backend/static/models/rooms`）に `hub.glb` があるか、指定していれば `WALK_MODEL_PATH` の GLB があるかを確認する） |
| 壁と床が無い（家具だけ浮いて見える） | 建物の GLB が見つからない。起動ログに `[Museum] <パス> が見つかりません (警告: この部屋の建物は表示されません …)` と出ている。`backend/static/models/rooms/`（または `HOME_ROOM_MODELS_DIR`）に `hub.glb` があるか確認する。開発用の GLB は `tools/home-rooms/build_rooms.py` で作り直せる |
