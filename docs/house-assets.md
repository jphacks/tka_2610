# 家の建物 GLB の仕様

> [!NOTE]
> **今の家は中央のリビング（`hub`）の 1 部屋だけで、必要なファイルは `hub.glb` の 1 つです。開口（出入口）はありません（4 面とも壁でふさぐ）。**
> 以前の 4 部屋の家（中央・左・右・前）の左・右・前の部屋と、hub の西・東・北の開口は消しました。下の「開口」「開いた側と共有の壁」や、左・右・前の部屋についての項目は、**部屋を戻すときだけ** 使います（今の GLB には入れません）。
> 家の建物の GLB を作ってもらうときの仕様です。いまは開発用のシェル（[tools/home-rooms/](../tools/home-rooms/README.md) で生成）が入っています。本番の GLB は、これと **同じファイル名・同じ作り** で置き換えます。
> 機械で確かめられる項目は `python3 tools/home-rooms/check_rooms.py <GLB のフォルダ>` で確認できます（最後に `ALL CHECKS PASSED` と出れば OK。今は hub だけを調べ、開口・床のつながり・開いた側・共有の壁の検査は隣の部屋が無いので飛ばします）。

## 部屋とファイル

1 部屋 1 ファイルです。アプリは各ファイルを部屋の origin へ **平行移動だけ** して置きます（回転・拡大はしない）。

| 部屋 id | 名前 | ファイル | origin（世界座標 x, z） | 内寸（x × z） | 壁 |
|---|---|---|---|---|---|
| `hub` | 中央のリビング | `hub.glb` | (0, 0) | 10 × 10 m | 4 面。開口なし（すべて閉じる） |

- 置き場所は `backend/static/models/rooms/`。ファイル名はバックエンドの部屋の定義（`backend/src/home.rs` の `ROOM_DEFS`）から参照します。
- 世界座標の範囲：x −5.24〜5.24、z −5.24〜5.24（壁の外の面まで）。

上から見た図（上が北 = −Z、下が南 = +Z・入口側。線は壁の外の面）：

```
     +----------------+
     |                |
     |                |
     |      hub       |
     |                |
     |                |
     +----------------+
```

部屋を戻すときの以前の値（参考。git の履歴にもあります）：

| 部屋 id | 名前 | ファイル | origin（世界座標 x, z） | 内寸（x × z） | 壁 |
|---|---|---|---|---|---|
| `hub` | 中央 | `hub.glb` | (0, 0) | 10 × 10 m | 4 面。西・東・北の壁の中央に開口。南は閉じる |
| `left` | 左 | `left.glb` | (−9.24, 0) | 8 × 8 m | 3 面。**東** を開ける（hub の西の壁が 4 面目） |
| `right` | 右 | `right.glb` | (+9.24, 0) | 8 × 8 m | 3 面。**西** を開ける（hub の東の壁が 4 面目） |
| `front` | 前 | `front.glb` | (0, −9.24) | 8 × 8 m | 3 面。**南** を開ける（hub の北の壁が 4 面目） |

- `front` は **−Z 側**（入口から入って正面、北）です。キット v1 の「front = +Z」とは逆です。
- 隣の部屋とは hub の壁を共有します（通路なし）。hub の外の面（±5.24）が、隣の部屋の内寸の面になります。家全体は x −13.48〜13.48、z −13.48〜5.24 でした。

## 共通の決まり

- glTF 2.0 のバイナリ（`.glb`）。テクスチャは埋め込む。
- 単位はメートル。**Y が上、+Z が手前（南・入口側）、+X が東（右）**。
- 原点 = その部屋の内寸の中心。**床の上面が y = 0**。ルートのノードに回転・拡大を入れない。
- 圧縮の拡張（`KHR_draco_mesh_compression`、`EXT_meshopt_compression`、`KHR_texture_basisu`）は使わない。Web は `useGLTF(url, false, false)` で読み、デコーダを入れていません。
- 天井・家具・照明・カメラは入れない（鑑賞モードの天井と照明はアプリが部屋ごとに作る）。
- 当たり判定は **見えている形そのもの** から作ります（`web/src/three/scenes/walk/collision.ts`）。見えない壁や当たり判定用の箱を入れない。逆に、見えている形にはすべて当たります。
- 大きさの目安：1 ファイル 3 MB 以下（開発用：hub 2.34 MB。いまの `home-empty.glb` は 1.4 MB）。メッシュのノードは 1 部屋 60 個以下（開発用：hub 34。開口と共有の壁があった 4 部屋のころの hub は 64）。
- ノードの名前に `Ceiling`・`ARTWORK_` で始まる名前、`home_rug` を含む名前を使わない（当たり判定から外れる）。

## 寸法

### 壁

| 項目 | 値 |
|---|---|
| 厚さ | 0.24 m（内寸の面から外へ。hub は内の面 ±5.0、外の面 ±5.24。部屋を戻すときの 8 × 8 の部屋は内の面 ±4.0、外の面 ±4.24） |
| 高さ | 4.2 m（上面 y = 4.2）。家のキットは 3.2 m だが、ホームの積み上げの建物で壁が低く見えないよう、天井の高い部屋にした |
| 下の壁 `wall_lower` | y = 0〜0.92。手前の壁のカットでも残る（腰の高さの壁） |
| 上の壁 `wall_upper` | y = 0.92〜4.2。手前の壁のカットで隠れる |
| 幅木などの飾りが壁の面から出る量 | 0.075 m 以下（開発用：幅木 0.0375、笠木 0.0485、回り縁 0.0565、蛇腹 0.07。開口を戻すときは開口の枠の足元 0.075） |
| 角の柱（任意） | 内側の角。上面は 4.2 m より低く（開発用 4.18 m）。壁の上面と同じ高さの面を作らない |

壁と飾りは、両面（部屋の内側と外側）とも仕上げます。壁の外側は家の外から（斜め上からの画面で）見えます（部屋を戻したときは、hub の共有の壁の外側が隣の部屋の壁として見えます）。

### 床

- 上面 y = 0。仕上げ（role `floor`、材質 `Floor_Oak`）の下に土台（role `foundation`、材質 `Foundation`）を入れ、下は y = −0.2 まで（開発用：仕上げ 0.025 m、土台 0.175 m）。
- 床の仕上げは内寸ちょうど（hub 10 × 10）。部屋を戻すときは、8 × 8 の部屋の開いた側も、hub の壁の外の面（内寸の面）までです。
- 壁の下にも土台を入れる（外から見て壁の下にすき間が出ないように。開発用は壁の厚さの土台を y = −0.2〜0）。
- 部屋を戻すときは、床どうしを段差・すき間なく続けます：hub の床（〜5.0）→ 開口の帯（5.0〜5.24、hub のファイル）→ 隣の部屋の床（5.24〜）。上面はすべて y = 0。

### 開口（部屋を戻すときだけ。以前の hub の西・東・北）

今の `hub.glb` には開口を入れません（サーバーの `house.rooms[].doors` も `[]`）。部屋を戻すときは、次の値で開けます。

| 項目 | 値 |
|---|---|
| 位置 | 壁の中央（壁に沿った中心のずれ `offset` = 0） |
| 区画 | 壁に沿って 3.0 m（±1.5）。キット v1 の `portal_arch_3m` と同じ |
| 有効幅 | 2.10 m（枠の内側、±1.05） |
| 高さ | 2.60 m（アーチの頂点）。開発用は半円アーチ（半径 1.05 m、起点 1.55 m）。四角い開口にするなら 2.10 × 2.60 m 以上 |
| 枠（jamb）とアーチ | 開口の外側（壁に沿って 1.05 m より外）に付ける。開口の内側へは出さない |
| 枠の足元の台など | 開口の内側へ出してよいのは、床から 0.2 m まで・0.025 m まで・壁の厚さより外（部屋の中）だけ（開発用は台が 0.0225 m 出る） |
| 開口の床 | 壁の厚さの帯（hub の内の面 5.0 〜 外の面 5.24）を **hub のファイル** が埋める。上面 y = 0、role `floor`。幅は少なくとも有効幅（開発用は区画の 3.0 m 全部） |
| 開口の中 | 有効幅 × 高さの範囲に、壁の厚さの両側 0.8 m まで、形を 1 つも置かない |

この値はサーバーの部屋の定義（`/api/museum` の `house.rooms[].doors[]` の `offset`・`clear_width`・`height`）と同じにします。変えるときは両方を合わせてください。

### 開いた側と共有の壁（部屋を戻すときだけ。以前の左・右・前の部屋）

今の家には隣の部屋が無いので、hub の壁は共有せず、`faceRoom` のメッシュも作りません。

- 開いた側（left の東、right の西、front の南）には **壁も幅木も置かない**。hub の壁がある場所（内寸の面より外）に形を置かない。
- 閉じた側の壁の端（開いた側の端）：壁本体は内寸の面（±4.0）で止め、幅木・回り縁は **hub の外側の幅木の面**（4.0 − その飾りが出る量）で止める。hub の幅木と重ねない。
- 角の柱を置くとき、開いた側の 2 本は hub の壁に 0.08 m まで埋まってよい（hub の内側の面へ突き抜けない）。
- 共有の壁の hub 側の作り：hub の西・東・北の壁の外側の面のうち、隣の部屋の中から見える範囲（壁に沿って ±4.0）は **別のメッシュ** にして、`extras.faceRoom` に部屋の id（`left`・`right`・`front`）を入れる。開発用は壁本体を厚さの半分（壁の中心線）で分けている。±4.0 より外（家の外から見える所）は `faceRoom` なし。

## ノードと extras（アプリが読むもの）

glTF の `extras` は three.js の `userData` になります。開発用シェルの作り：

```
scene（name = 部屋 id、extras = ルートと同じ）
└ {id}__shell                       ルート。extras { roomId, dimensionsMeters: [w, 3.2, d], … }
   ├ {id}__floor                    子：Floor（floor）、Floor_Foundation（foundation）
   ├ {id}__wall_{side}              1 辺に 1 つ。extras { side, cutaway }
   │  ├ Wall_Lower・Wall_Upper・Trim_Lower・Trim_Upper・Wall_Foundation（それぞれ role）
   │  ├ Wall_Lower_Room・Wall_Upper_Room          hub の共有の壁だけ（部屋を戻すとき）。extras { role, faceRoom }
   │  └ hub__wall_{side}__door      hub の開口（部屋を戻すとき）。extras { side, cutaway, door: { side, offset, clearWidth, height, bay } }
   │     └ Door_Wall_Lower(_Room)・Door_Wall_Upper(_Room)・Door_Trim_Lower・Door_Trim_Upper・Door_Floor・Door_Foundation
   ├ {id}__open_{side}              隣の部屋の開いた側の印（部屋を戻すとき。形なし）
   └ {id}__corner_{ne|nw|se|sw}     角の柱。extras { side: 'corner' }、子：Oak_Column・Foot・Capital（trim）
```

### 必ず守るもの

| どこ | extras | 値 |
|---|---|---|
| ルート（scene の唯一のノード） | `roomId` | 部屋 id |
| | `dimensionsMeters` | `[内寸の幅, 3.2, 内寸の奥行き]`（hub `[10, 3.2, 10]`。部屋を戻すときの 8 × 8 の部屋は `[8, 3.2, 8]`） |
| ルートの子 | ノード名 | `{部屋 id}__` で始める |
| 壁のノード（1 辺に 1 つ、ルートの子） | `side` | `north`・`south`・`east`・`west` |
| | `cutaway` | 南東から見るときに隠すか（true / false。下の表。今のアプリは読まない） |
| メッシュのノード（壁のノードの下のどこでもよい） | `role` | `floor`・`foundation`・`wall_lower`・`wall_upper`・`trim_lower`・`trim_upper`・`trim` のどれか |
| hub の共有の壁の、部屋側の面のメッシュ（部屋を戻すときだけ） | `faceRoom` | 隣の部屋の id（`role` は `wall_lower` か `wall_upper`） |
| 角の柱のノード（ルートの子） | `side` | `'corner'`。ノードの位置（translation）は柱の位置（どの角かを位置の符号で見る） |
| 開いた側の印（部屋を戻すときの隣の部屋、ルートの子、形なし） | `side`・`open`・`cutaway` | `side` = 開いた向き、`open: true`、`cutaway` = hub のその壁と同じ（right だけ true） |

ルートの extras には、ほかに `wallThickness`・`wallHeight`・`floorTopY`・`cutaway`・`sharedWalls`（hub。今は `[]`）を入れています（参考。アプリは今のところ読みません）。部屋を戻すときは `doors`（hub）・`openSide`（隣の部屋）も入れます。開発用シェルは `devShell: true`。本番は `false` か入れない。

### 材質

材質は次の 4 つだけにします（名前で見分けます）。

| 材質名 | 使う所 |
|---|---|
| `Wall_Plaster` | 壁（`wall_lower`・`wall_upper`）。白い漆喰 |
| `Floor_Oak` | 床（`floor`） |
| `Trim_Oak` | 幅木・回り縁・角の柱（開口を戻すときは開口の枠とアーチも）（`trim_lower`・`trim_upper`・`trim`） |
| `Foundation` | 床と壁の下の土台（`foundation`）。テクスチャなしの暗い色 |

## アプリが role・cutaway・faceRoom で何をするか

- **壁紙と床材**（`web/src/three/scenes/home/theme.ts`）：role が `wall_lower`・`wall_upper`・`floor` のメッシュだけ材質を差し替えます。選んだ仕上げが焼き込みと同じ（白壁 `Wall_Plaster`・オークの床 `Floor_Oak`）なら GLB の材質のまま。幅木・柱・土台はそのまま。内装セット（`textures/finish-pack/`）の壁紙・床材は焼き込みが無いので、いつもテクスチャを貼ります（UV は下の決まりのまま使う。`npm run check:theme` が本番の GLB でも確かめられます。`HOME_ROOM_MODELS_DIR` で GLB のフォルダを渡す）。
  部屋を戻したときは、`faceRoom` のメッシュに、その部屋（隣の部屋）の壁紙を当てます（`HouseShells.tsx` が `faceThemes` を渡す）。
- **手前の壁のカット**（`home/cutaway.ts`、斜め上から見る画面だけ）：カメラの側の 2 面（部屋の中心から見たカメラの位置で、東か西・南か北を選ぶ）と、家全体を見下ろす画面では出入口のある壁（`house.rooms[].doors[].side`。今は出入口が無いので無い）を、`side` で見分けて、その壁のノードの下にある `wall_upper`・`trim_upper` を隠します。カメラが回ると隠す壁も入れ替わります。角の柱は、位置の符号で決まる 2 つの向き（東西・南北）がどちらもカットされる角のものだけを丸ごと隠します。部屋を戻したときは、家全体を見下ろす画面で、隣の部屋の開いた側も出入口の向き（`doors`）としてこの判定に入ります（4 部屋のころは、right の南西の柱が、カットした手前の角に 1 本だけ立ち残らないようにしていました）。`cutaway` の印（壁と開いた側の印の両方）は読みません。
- **当たり判定**：見えているメッシュすべて（一人称で歩く画面はカットしない）。

## テクスチャと UV

- 画像は `backend/static/home/textures/` の素材と同じ作りにします（テーマで差し替えたときと見た目がそろう）。
  - base（色）：JPEG・sRGB。normal と ORM：PNG・リニア。いまの素材は base 1024 px、normal・ORM 512 px（開発用シェルはキット v1 の 1024 px を埋め込んでいる）
  - normal は OpenGL 向き（+Y）。接線は入れなくてよい（three.js が作る）
  - ORM は R = 遮蔽（255 固定）、G = 粗さ、B = 金属
- 1 枚の大きさ：壁の漆喰・オークは 1 m 角、オークの床は 2 m 角（`catalog.json` の `materials[].tileMeters`）。
- UV の決まり（`theme.ts` が repeat と offset をこれに合わせて計算する）：
  - 壁：**1 UV = 1 m**。壁の表と裏の面は `v = y − 0.46`（`wall_lower`）、`v = y − 2.56`（`wall_upper`。上の壁の真ん中の高さ (0.92 + 4.2) / 2）。`u` は壁に沿った距離（原点はどこでもよい）
  - 床：**1 UV = 2 m**（`u = x / 2`、`v = z / 2`。原点はどこでもよい）
  - 幅木・柱など（差し替えない所）は自由

## 開発用シェルで確かめたこと

`check_rooms.py` で次を確かめています（今の `hub.glb`。2,342,780 バイト、メッシュのノード 34、9,144 三角形）。

- ノード名・extras・材質・角の柱 4 本・UV の決まりが仕様どおり
- 壁の外の面（±5.24）より外へ出る量：壁・床・土台は 0、外側の飾りだけ（下 `trim_lower` 0.0485 m・上 `trim_upper` 0.07 m。0.075 m 以下）
- 家全体で、同じ平面・同じ向きで重なる面が 0
- 開口・床のつながり・開いた側・共有の壁は、隣の部屋が無いので調べない（部屋を戻して `check_rooms.py` の `EXPECT` などに部屋を足すと、また調べる）

4 部屋のころは、上に加えて、hub の 3 か所の開口の中を通る光線（1 か所 1654 本）が何にも当たらないこと、hub の中から開口をくぐって隣の部屋の奥まで床が y = 0 で続くこと（1 か所 2410 点）、左・右・前の部屋の開いた側に形が無いこと（光線 1681 本）、共有の壁の `faceRoom` の付き方、隣の部屋の形が hub の壁へ入り込む量（角の柱だけ 0.08 m）も確かめていました。Khronos の glTF Validator でもエラー 0 でした（警告は「法線マップに接線が無い」だけ）。
