# 鑑賞モード（家の中を three.js で一人称で歩く）

> [!NOTE]
> 歩く場所は家で、中央の 10 × 10 m のリビングの 1 部屋だけです。出入口は無いので、歩けるのはリビングの中だけです（以前あった左・右・前の部屋は消しました）。家具と作品は配置 JSON のとおりに置き、家具にも当たります。壁紙と床材（テーマ）も、⑫ 模様替えで選んだものがほかの 3D 画面と同じように付きます。作品は、登録時に GLB から測った実寸を置き場所の枠に収めた大きさで置きます（ほかの 3D 画面と同じ）。
> 建物の GLB（今は `hub.glb` だけ）は、開発用のシェル（`tools/home-rooms/` で生成）です。本番の GLB の仕様は [house-assets.md](house-assets.md) にあります。
> 博物館のころの別館・焼き込んだ光（ライトマップ）・看板の文字の直し（Caption）は消しました。博物館用の高画質版 GLB（`museum-walk.glb`）と、それを作る Blender のスクリプト（`tools/walk-stage/`）も消しました。git の履歴にだけあります（下の「旧博物館の資料（旧版）」）。
> 3D の表示は Web（three.js）だけで完結します。
> PC（キーボードとマウス）とスマホ（タッチ）のどちらでも歩けます。スマホでは、画面の仕上げを省いた軽い表示になります（下の「スマホ（タッチ）」）。

## 使い方

- 画面：`/museum/walk`（`?room=おへやID`。おへやの画面 `/rooms/:id` の「歩く」、⑤ おうちの中 →「⋯」→「鑑賞モード」。⑫ 模様替えの右上の「鑑賞モードへ」からも開ける。どれも PC とスマホの両方で出る。歩けるのはそのおへやの中だけ）
- 操作（PC）：クリックで歩き始める、W A S D（矢印キー）で歩く、マウスで見回す、Shift で速く歩く、Esc で操作をやめる
- 操作（スマホ・タッチ）：「歩き始める」を押す。画面の左側に親指を置くと、そこに仮想スティックが出て、引いた向きに歩く（端まで引くと速く歩く。離すと止まる）。右側を指でなぞって見回す。左右の指は同時に使える。右上の「やめる」で操作をやめる（下の「スマホ（タッチ）」）
- 作品を見る：照準（画面の中心の丸）を 3.5m 以内の作品に合わせると、作品の名前が出ます。PC は E かクリック、スマホは名前の下の「見る」か画面の右側の軽いタップで、作品カード（作品名・作者・日付・メモ・おもいでの数・部屋）を出し、「詳しく見る」で作品の詳細画面（⑥）へ進めます。声のおもいでがある作品は、カードの「声をきく」で流せます。
- 声のおもいで：声のある作品は、照準を合わせると名前の横に音符が出ます。そのまま 1 秒見ていると、その作品の最初の声を 1 回流します（同じ作品は、画面を開いている間に 1 回だけ。目をそらす・ほかの作品へ移ると、小さくして止める）。流している間は画面の下に「『〇〇』の声」と止めるボタンが出ます。右上の音符のボタンで自動再生を入・切できます（`localStorage` の `walk-auto-voice` に覚える。はじめは入）。歩き始めのクリック・タッチのあとに流すので、ブラウザの自動再生の制限にはかかりません（`pages/MuseumWalk.tsx` の `useWalkVoice`）。カードは Esc か「閉じる」で閉じます（スマホは閉じるとそのまま歩き続けられる）。詳細画面から戻ると、元の場所と向きから歩き続けられます。
- 歩ける場所：はじめはリビングの南側に立っています。リビングの 4 面の壁はふさがっていて出入口が無いので、リビングの中だけを歩きます（部屋と出入口を戻したときは、出入口をくぐってほかの部屋へ歩いて行けます。当たり判定は全部の部屋をまとめて作るため）。
- 家具と壁：ソファ・棚・机・台などの家具と壁には当たって止まります。ラグの上は歩けます。見上げると天井があります。
- 飾る作品の反映：`/api/museum` を 3 秒ごとに取り直します。ほかの端末で飾る・外すと、歩いている間に作品が現れたり消えたりします。
- 模様替えの反映：ほかの端末やタブの ⑫ 模様替えで家具を動かす・足す・消す、テーマを変えると、3 秒以内に置き直され、壁紙と床材も変わります。当たり判定と影も新しい配置で作り直します（下の「当たり判定」）。
- PC とスマホのどちらでも使えます。どちらの操作にするかは端末で決めます（PC でもタッチの操作を試せます。下の「操作の種類の決め方」）。

## スマホ（タッチ）

### 操作の種類の決め方

- `web/src/three/scenes/walk/inputMode.ts` の `isTouchDevice()` で決めます。ホバーできず指で触る端末（CSS の `(hover: none) and (pointer: coarse)`）ならタッチの操作、それ以外は PC の操作です。
- 画面（`MuseumWalk.tsx`）が開いたときに 1 回だけ決めて、`WalkScene` に `touch` で渡します（画面の説明と、3D の操作・表示を食い違わせないため）。開いている間は変わりません。画面は `three/index.tsx` から読みます（`inputMode.ts` は three.js を使わない）。
- **開発用の切り替え**：PC でタッチの操作を試すときは、URL に `?input=touch` を付けて開きます（例：http://localhost:5173/museum/walk?input=touch）。メニューから開いてもタッチのままにしたいときは、ブラウザの開発者ツールのコンソールで `localStorage.walkInput = 'touch'` とします（戻すときは `localStorage.removeItem('walkInput')`）。`'pointer'` にすると、タッチの端末でも PC の操作になります。URL と localStorage の両方があれば、URL のほうを使います。
- タッチの操作はマウスでも動くので（左側をドラッグで歩く、右側をドラッグで見回す、右側をクリックで作品を見る）、PC でも確かめられます。表示も下の軽い表示になります（作品の GLB を置く数だけは端末で決まるので、PC では全部置く）。

### 操作（`walk/TouchControls.tsx`）

| 場所 | 操作 | 中身 |
|---|---|---|
| 画面の左 45% | 指を置いて引く | 指を置いた所に仮想スティック（半径 56 px）が出て、引いた向きに歩く。半径の 10% までは止まったまま、その先は引いた量に合わせて速くなる。90% より先まで引くと速く歩く（PC の Shift と同じ速さ）。離すと止まる |
| 画面の右 55% | なぞる | 見回す。1 px なぞるごとに横は 0.3°、縦は 0.22° 回る（画面の大きさによらない。縦長のスマホの横幅 390 px いっぱいで約 117°、150 px 下へなぞると約 33° 見下ろす）。上下の限度は PC と同じ。1 回で 160 px を超える動きは、異常な値として無視する |
| 画面の右 55% | 軽くタップ（動き 10 px 未満・0.3 秒未満） | 照準の先に作品があれば、作品カードを開く（名前の下の「見る」と同じ） |

- 指は `pointerId` で見分けるので、左の指で歩きながら右の指で見回せます（左右 1 本ずつ。それより多い指は無視します）。
- Pointer Lock は使いません。歩き始める・やめるは画面の「歩き始める」「やめる」で決めて、`WalkScene` の `walking` で渡します。作品カードを開いている間は止まり（スティックも消える）、閉じるとそのまま歩けます。
- スティックの見た目は画面が DOM で描きます（`MuseumWalk.tsx` の `WalkStick`。輪とつまみ。3D の上で毎フレーム変わるので、ガラスのぼかしは使わない）。`WalkScene` の `onStick` で、指を置いた所とつまみの位置（`TouchStick`。キャンバスの左上からの px）が届きます。変わったときだけ、1 フレームに 1 回までで、指を離すと null です。状態は `WalkStick` だけが持ち、画面全体と 3D は描き直しません。
- キャンバスに `touch-action: none`、画面に `overscroll-behavior: none` を付けて、なぞってもページがスクロール・拡大・再読み込みしないようにしています。長押しで文字の選択やメニューも出ません。上の操作列（戻る・やめる）は、横向きのときも切り欠き（safe area）の内側に置きます。
- 数値（範囲の割合・スティックの半径・止まったままの範囲・速く歩く所・回る角度・タップの見分け方）は `TouchControls.tsx` の冒頭の定数と、`inputMode.ts` の `TOUCH_STICK_RADIUS` です。

### 軽い表示（lite）

タッチの端末では、スマホの GPU でもなめらかに歩けるよう、`WalkScene` が次のように軽くします。PC の見た目は変わりません。

| 項目 | PC | タッチ（lite） |
|---|---|---|
| 画面の仕上げ（`PostEffects`：隅の陰 GTAO・光のにじみ・MSAA） | あり | なし。ふちのギザギザは Canvas の `antialias` で取る |
| トーンマッピングと sRGB への変換 | `PostEffects` の最後の `OutputPass` が、renderer の設定（Neutral・sRGB）で行う | 描くときに renderer がそのまま同じ設定で行う。色と明るさはそろう（隅の陰と光のにじみが無い分だけ違う） |
| 描画の細かさ（dpr）の上限 | 1.5 | 1.25（どちらも、重いときは `PerformanceMonitor` が 1 まで下げる） |
| 作品のスポットライト | 近い 6 つ | 近い 2 つ（`ArtworkSpotlights` の `maxLights`） |
| ダウンライト | リビングの 5 灯 | 5 灯（リビングは減らさない。小さい部屋（短い辺が 9 m 未満）があれば、その部屋は中央の 1 灯だけ。`roomLights.smallLite`） |
| 太陽の影の細かさ | 2048 px | 1024 px（影は動かないので、作り直したときだけ描くのは同じ） |
| 映り込みの細かさ（立方体の 1 面） | 128 px | 64 px |

three.js はライトの数だけ画面のすべての点で計算するので、スマホではライトの数を減らしています。部屋全体の明るさは環境光と太陽で保たれるので、ダウンライトを減らしても暗くはなりません（床の淡い光だまりが減るだけです）。
作品の GLB を置く数は、ほかの 3D 画面と同じく `HomeObjects` が端末で決めます（`pointer: coarse` の端末は、カメラに近い 6 つ）。

## 何を読み込んでいるか

| もの | 読み込み元 |
|---|---|
| 家の建物（ステージ） | `/api/museum` の `house.rooms[].model_url`（部屋ごと。今は hub だけ）。サーバーの `HOME_ROOM_MODELS_DIR`（既定は `backend/static/models/rooms`）の `hub.glb` を `/media/museum/room-<部屋 id>-〇〇.glb` として配信している。`HouseShells` が部屋ごとに読み込み、部屋の中心（`house.rooms[].origin`）へ平行移動して並べる。ほかの 3D 画面と同じ GLB。`model_url` が null の部屋は建物を描かない。`house` の無い古いサーバーのときだけ、`model_url`（リビングだけの `home-empty.glb`）を 1 つ読む |
| 歩く画面だけの別の建物 | `/api/museum` の `walk_model_url`。サーバーの `WALK_MODEL_PATH` を指定したときだけあり、ふだんは無い。あれば **リビングの建物の代わりに** 使う |
| 家具 | `/api/museum` の `layout`（配置 JSON）と `catalog`（家具の GLB の URL・大きさ・作品を載せる面）。GLB は `/home-assets/modules/〇〇.glb`（`backend/static/home/modules/`）。ほかの 3D 画面と同じ `HomeObjects` で置く |
| 飾っている作品 | 置く場所は `layout`、モデルの URL・種類・実寸（`artwork.model_size`）・収める枠（`fit`）は `slots`。`HomeObjects` が家具の面（天板・本棚の段）の上か床に、実寸 × 倍率（`home/placement.ts` の `displayScale`。`slots[].scale` と同じ値）の大きさで置く。実寸が分からない作品は枠に収める。作品の照明（`walk/ArtworkSpotlights.tsx`）は今も枠 `fit` の高さで狙う点を決め、本棚の段の作品だけ、上の棚板の下から光が入るよう低く遠くから当てる |
| 壁紙・床材（テーマ） | `/api/museum` の `layout.rooms[部屋]` の `wall`・`floor`（部屋ごと）と、`catalog.materials`（テクスチャの URL と 1 枚の大きさ）。部屋ごとの `MuseumModel` が `home/theme.ts` で壁と床の材質を差し替える（ほかの 3D 画面と同じ） |
| 天井 | 建物の GLB には天井が無いので、`WalkScene` が部屋ごとに、壁の高さ（4.2 m）に板（`Ceiling_<部屋 id>`。部屋の内寸より 0.6 m 大きく、壁の中まで届かせる）を張る。位置と大きさは `house.rooms` から |
| 天井の照明（ダウンライト） | 部屋ごとに `house.rooms` の位置と大きさから作る（`walk/stagePreset.ts` の `roomDownlights`。下の「ステージの設定」） |
| 作品カードの中身 | `/api/artworks/:id`（詳細画面と同じ。おもいでの `memories` も） |
| はじめの位置・歩き方・カメラ・照明・当たり判定から外すもの | `web/src/three/scenes/walk/stagePreset.ts` の `HOME_STAGE` |

ほかの画面（ホーム・おうちの中・マップ・模様替え）は手前の壁の上の部分をカットしますが、鑑賞モードではカットしません。

### 家の建物の GLB（部屋ごと）の作り

詳しい仕様は [house-assets.md](house-assets.md) にあります。鑑賞モードに関係するところだけを書きます。

- 1 部屋 1 ファイルで、部屋の中心が原点、床の上面が y = 0 です。回転・拡大はせず、部屋の中心へ平行移動するだけで並びます。今は `hub.glb`（中心 (0, 0)、内寸 10 × 10 m、壁の高さ 4.2 m・厚さ 0.24 m、出入口の無い 4 面の壁）だけです。
- 部屋と出入口を戻したときは、隣の部屋とリビングの壁を共有し、出入口の下の帯（壁の厚さの分）の床はリビングの GLB に入れます。出入口の中を通る形は何も置かないので、そのまま歩いて通れます。共有する壁の、隣の部屋に向いた面には `userData.faceRoom`（部屋の id）を付け、その部屋の壁紙が付きます（`home/theme.ts`）。
- 天井・家具・照明は入っていません（天井と照明は `WalkScene` が部屋ごとに作る）。当たり判定は見えている形そのものから作るので、見えない壁や当たり判定用の箱は入れません。
- 壁のノードの `userData` に `side`（north / south / east / west）と `cutaway` が入っています。子のメッシュの `userData.role` は `floor`・`wall_lower`・`wall_upper`・`trim_lower`・`trim_upper` などです。`side` と `role` は、手前の壁のカット（`home/cutaway.ts`。カメラの側の壁を隠す。鑑賞モードでは使わない）と、壁紙・床材の切り替え（`home/theme.ts`。`wall_lower`・`wall_upper`・`floor` の材質だけを差し替える）で使います。`cutaway` の印は、今のアプリは読みません。
- 材質は `Foundation`・`Floor_Oak`・`Wall_Plaster`・`Trim_Oak` の 4 つです。
- 名前が `Ceiling`・`ARTWORK_` で始まるノード、名前に `home_rug` を含むノードは当たり判定から外れるので、建物の GLB では使いません。
- 部屋ごとの GLB にする前の `home-empty.glb`（8 × 8 m のリビングだけ。部屋を広げる前の大きさ。床のタイル 64 枚・壁 32 枚・角の柱 4 本）は、前の版の Web のために残しています。今の鑑賞モードは、`house` の無い古いサーバーのときだけ読みます。

## ステージの設定（`HOME_STAGE`）

| 項目 | 値 | メモ |
|---|---|---|
| はじめの位置 `spawn` | (0, 0.12, 3.0) | 南側（工作机の手前）に立つ |
| はじめに向く先 `lookAt` | (0, 0, 0) | 部屋の中央（ソファの方） |
| 歩く人 `player` | 身長 1.8 m、半径 0.26 m、目の高さ 1.62 m、2.8 m/秒（Shift で 4.6 m/秒）、重力 18 m/秒²、段差 0.3 m | 目の高さ以外は Unity 版の `MuseumWalker` と `CharacterController` と同じ |
| カメラ `camera` | 視野角 61°、near 0.045 m、far 60 m | 視野角は縦の角度。縦長の画面（横 / 縦 < 1）では `61 + (1 − 横 / 縦) × 30`°（上限 80°）に広げる（`WalkScene.tsx` の `ResponsiveFov`。縦向きのスマホ 390 × 844 で約 77°）。横が狭くなりすぎて、拡大したように見え、見回すと大きく動いて見えるのを防ぐ。横長の画面（PC・横向き）ではそのまま |
| 太陽 `sun` | 向き 50° / -35°、色 (1, 0.94, 0.84)、強さ 0.9、影の濃さ 0.6 | 天井の板は影を落とさないので、天窓から差すように床を照らす。床が白く飛ばないよう 1.2 から下げた |
| 環境光 `ambient` | 上 (1, 0.97, 0.91)、横 (0.86, 0.82, 0.74)、下 (0.69, 0.65, 0.55) | Unity の Trilight と同じ考え方の 3 色 |
| 映り込み `reflection` | 位置 (0, 1.6, 0)、強さ 0.4 | リビングの中央から 1 度だけ撮る（部屋が 2 つ以上あるときも、この 1 枚を使う） |
| 天井の照明 `roomLights` | 部屋ごとのダウンライト。リビング（短い辺が 9 m 以上の部屋）は 5 灯：部屋の中心から (±2.5, ±2.5) の 4 灯と中央。高さ 3.15 m、色 (1, 0.93, 0.82)、強さ 1.0、届く距離 6 m、広がり 100°。位置は `house.rooms` から `roomDownlights` が作る（今の家はリビングだけなので 5 灯。スマホの軽い表示でも 5 灯）。小さい部屋（以前の 8 × 8 の部屋）を戻したときは、その部屋は 3 灯（中央と、リビングからその部屋へ向かう向きに ±2.4 m）、スマホでは中央の 1 灯だけ（`smallLite`） | 真下に向ける。影なし。強さ 2.2・距離 7 m では真下の床が白く飛んでいたので下げた。部屋全体の明るさは環境光と太陽で保ち、ダウンライトは床に淡い光だまりを作る程度にしている。部屋を広げたときも灯の数は変えず、間隔だけ広げた（リビングは壁から 2.5 m。スマホの負担を増やさないため） |
| `spotLights` | リビングだけの 5 灯（上の並べ方で、リビング 1 部屋分） | `MuseumDaylight` に灯を渡さないときの既定。今の鑑賞モードは `roomLights` から作った灯を渡す（`house` の無い古いサーバーでも、リビング 1 部屋として同じ 5 灯になる） |
| 光る材質 `emissive` | なし | |
| 当たり判定から外すもの `collisionIgnore` | 名前が `ARTWORK_` か `Ceiling` で始まるもの、名前に `home_rug` を含むもの | 作品と天井（部屋ごとの `Ceiling_<部屋 id>`）には当たらない。ラグの上は歩ける |
| `legacyUnityColors` | false | 博物館の GLB は色を sRGB として読み直していた。家の GLB は glTF の決まりどおりなので、そのまま使う |

照明の強さは Unity の単位で書いてあり、three.js への換算は `lighting.tsx` の冒頭にあります。家に合わせて決めた値で、Unity 版の値ではありません。

## 当たり判定

- `WalkScene` の `stageRef`（グループ）の中に、家の建物（`HouseShells`。全部の部屋）と家具・作品（`HomeObjects`）を入れ、このグループの形から当たり判定を作ります（`collision.ts`）。全部の部屋をまとめて 1 つの当たり判定にするので、部屋と出入口を戻したときは、出入口をくぐって部屋から部屋へそのまま歩けます（今はリビングだけ）。壁・床・家具は、見えている形そのものに当たります。
- 建物は部屋ごとに読み込まれます。**`model_url` のある部屋の建物が全部そろうまで、当たり判定を作らず、歩き始められません（`ready` にならない）。** 床の無い部屋へ歩いて落ちないようにするためです。部屋の建物を読み込むたびに（`HouseShells` の `onLoaded`。部屋の id つき）材質はすぐに整え、全部そろったところで作り直します。
- 家具と作品は 1 つずつ後から読み込まれます。そこで、建物がそろったときと、`HomeObjects` の `onReady` のたびに作り直します（続けて呼ばれても、まとめて 1 回）。作り直すのは、材質の調整・当たり判定・影の範囲で、そのあと影と映り込みを撮り直します（0.03 秒ほど）。建物を読み込むまでの太陽の影の範囲は、`house.rooms` から求めた家全体の外形です。
- 外すもの：作品（`ARTWORK_`）、天井（`Ceiling` で始まる名前。部屋ごとの `Ceiling_<部屋 id>`）、ラグ（家具の GLB の中のノード名 `home_rug`）。名前は親のノードまでさかのぼって調べます。
- 作り直すきっかけは、次の 3 つです。
  - 家具や作品の GLB が載る・外れるとき（家具を足す・消す、作品を飾る・外す）
  - 置いてある物の位置・向き・部屋が変わったとき（⑫ 模様替えで家具を動かす・回す）。GLB は載り外ししないので、`HomeObjects` が配置の位置と向き（と部屋の中心）を比べて `onReady` を呼ぶ
  - テーマで壁と床の材質が変わったとき（テクスチャを読み込み終わってから差し替えたときも）。部屋ごとの `MuseumModel` が `onLoaded` をもう一度呼ぶので、差し替わった材質をこの画面用に整え直す（`stageMaterials.ts`）

## 見た目の工夫

どれも鑑賞モードだけで、ほかの 3D 画面（ホーム・おうちの中・マップ）の見た目は変わりません（テクスチャのくっきりさを除く）。
スマホ（タッチ）の軽い表示では、隅の陰と光のにじみは無く、作品の照明は 2 つまでです（上の「軽い表示」）。

| 工夫 | 内容 | ファイル |
|---|---|---|
| 隅の陰 | 壁と床の境目、家具の足もとなどをうっすら暗くする（GTAO） | `PostEffects.tsx` |
| 光のにじみ | 明るいところが少しにじむ（ブルーム） | `PostEffects.tsx` |
| 映り込み | 環境マップは映り込み（鏡面反射）にだけ効かせる（Unity の反射プローブと同じ考え方） | `stageMaterials.ts`、`lighting.tsx` |
| ガラス | 板そのものは光らず、景色を映すだけにした（日が当たっても白い膜にならない） | `stageMaterials.ts` |
| 作品の照明 | 近くの作品 6 つ（スマホの軽い表示では 2 つ）までを、上から作品用のスポットライトで照らす（本棚の段の作品は、上の棚板にさえぎられないよう低く遠くから。照明は 3.0 m より上に置かない）。歩くのに合わせて付け替える | `ArtworkSpotlights.tsx` |
| くっきりさ | 床や作品を斜めから見ても模様がぼやけない（異方性フィルタ） | `SharpTextures.tsx` |
| 影 | 建物・家具・作品の影は毎フレームではなく、当たり判定を作り直したときだけ描き直す | `lighting.tsx` の `StaticShadows` |

## まだできていないこと

- **スマホでの操作の調整**：実機でのなぞる速さ・スティックの大きさなどの調整はまだです（数値は `TouchControls.tsx` の冒頭）。傾き（ジャイロ）で見回す・2 本指の操作はありません。
- **スマホで作品が入れ替わるとき**：スマホでは作品の GLB をカメラに近い 6 つだけ置く（`HomeObjects`）ので、歩いて入れ替わるたびに当たり判定・影・映り込みを作り直します（ほかの物が載り外ししたときと同じ。重い端末では一瞬止まるかもしれません）。
- **天井**：部屋ごとに板 1 枚です。照明器具の形はありません（光だけを置いています）。
- **出入口**：今の家には出入口がありません（左・右・前の部屋と一緒に消しました）。以前の出入口も開口（アーチ）だけで、扉はありませんでした。
- **建物の GLB**：今は開発用のシェルです。本番の GLB は [house-assets.md](house-assets.md) の仕様で作ってもらい、`backend/static/models/rooms/` の同じ名前のファイルを置き換えます。
- **映り込みの撮り方**：リビングの中央から 1 枚だけ撮っています。部屋を戻したときは、ほかの部屋の金属やガラスにも、リビングの景色が映ります。
- **映り込みの細部**：Unity の反射プローブの「ボックス投影」はありません。金属やガラスに映る景色の位置が少しずれます。
- **作品の立体化**：写真から作る作品は、今も「写真を板に貼った」形です（`backend/src/glb.rs`）。サンプルの作品 33 点と、登録時に GLB を渡した作品だけが立体です。

## 広げるとき

部品を分けてあるので、次のように足していけます。

- **鑑賞モードの中で模様替えする**：今は ⑫ 模様替え（`/home/edit`）で動かします。歩きながら動かすときも、配置 JSON を `PUT /api/home/layout` で保存すれば `HomeObjects` が置き直し、当たり判定も作り直されます。置けるかどうかは `home/placement.ts` の `canPlace`（Rust の `backend/src/home.rs` と同じ計算。作品の実寸は `sizesFromSlots(slots)` を `ctx.sizeOf` に渡す）で調べられます。
- **テーマを増やす**：`backend/static/home/catalog.json` の `themes`（壁紙と床材の組み合わせ）に足します。`catalog.json` は Rust に埋め込んでいるので、サーバーのビルドし直しと、`home.rs` のテスト（`catalog_has_fourteen_furniture_with_japanese_names` のテーマの数）の直しが要ります。壁紙・床材の名前は、Rust の `home.rs`（`WALLS`・`FLOORS`）、`web/src/api/types.ts`（`WallFinish`・`FloorFinish`）、`home/theme.ts` の対応表にあるものだけ使えます。新しい素材を足すときは、この 3 か所とテクスチャ（`backend/static/home/textures/`）を合わせて足します。
- **部屋の形を変える・部屋を増やす**：部屋の位置・大きさ・出入口は `backend/src/home.rs` の `ROOM_DEFS` だけにあり、鑑賞モード（建物の配置・天井・ダウンライト・影の範囲）は `/api/museum` の `house` から作るので、Web の数値は直さなくて済みます。部屋の GLB（[house-assets.md](house-assets.md)）も合わせて用意します。部屋を増やすときは、配置 JSON の `rooms`（Rust の `Rooms`。今は hub だけ。Web の `RoomId` には以前の `left`・`right`・`front` も残している）が決まっているので、そこも変え、配置の版を上げます（手順は [AGENTS.md](../AGENTS.md) の「構成」）。
- **照明を変える**：`stagePreset.ts` の `roomLights`（部屋ごとの並べ方）を編集できるデータにすれば、照明の追加や移動もできます。

## 確認の仕方

- ビルド：`cd web && npm run build`
- 動作：サーバー（`cd backend && cargo run`）を起動し、`cd web && npm run dev` で http://localhost:5173/museum/walk を開く
- 見るところ：ソファ・机・壁で止まる、ラグの上は歩ける、照準を作品に合わせて E で作品カードが出る、見上げると天井とダウンライト（5 灯）がある、リビングの 4 面の壁のどこからも外へ出られない
- タッチの操作：PC なら http://localhost:5173/museum/walk?input=touch を開く（マウスのドラッグで試せる）。スマホなら、PC と同じ Wi-Fi で `http://<PC の IP アドレス>:5173/museum/walk` を開く（開発サーバーは `host: true` で、ほかの端末からも開ける）。見るところ：「歩き始める」のあと、左の指で歩き、右の指で見回せる（2 本同時でも）、ページがスクロール・拡大しない、作品に照準を合わせると「見る」が出て押すとカードが開く、カードを閉じるとそのまま歩ける、「やめる」で説明に戻る
- 反映：別のタブで作品を飾る・外すと、3 秒ほどで鑑賞モードに現れる・消える
